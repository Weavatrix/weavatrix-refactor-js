# Weavatrix Refactor JS 0.1.6

The first release under the `weavatrix-refactor-js` package and the
`sergii-ziborov/weavatrix-refactor-js` repository. It continues the JavaScript
refactoring engine while the canonical `weavatrix-refactor` package moves to a
native Rust MCP host, mirroring the `weavatrix` / `weavatrix-js` split.

The version continues the old line rather than restarting: `weavatrix-refactor`
went up to 0.1.5, so this is 0.1.6. There is no `weavatrix-refactor@0.1.6` and
there will not be — the next release under that name is the Rust host at 1.0.0.
To stay on JavaScript, install `weavatrix-refactor-js` or pin
`weavatrix-refactor@0.1.5`.

## Migration

- The npm package, executable, MCP Registry identifier, repository links, skill
  name and release workflow now consistently use `weavatrix-refactor-js`.
- Install and run with `npx -y weavatrix-refactor-js <repoRoot>`.
- The refactor home moved from `~/.weavatrix-refactor` to
  `~/.weavatrix-refactor-js`. This is deliberate: the Rust host owns the old
  path, and two different implementations must never share a repository lock, a
  confirmation-token store, or a rollback journal. A rollback bundle written by
  an earlier release stays in the old directory — finish or discard any pending
  rollback before upgrading, or point `WEAVATRIX_REFACTOR_HOME` at the old path.

The 11 tools, their schemas, the `weavatrix.edit-plan.v1` envelope, every result
state, and the three write gates are unchanged. The host dependency remains
`weavatrix-js` 0.3.15.

## Rename could claim COMPLETE while missing real references

The language-server session was seeded only from graph reach, and the
graph-remainder check that would downgrade the result consulted that same
inventory. Two nominally independent sources shared one blind spot: a call at
module top level has no containing symbol, so it produces no graph edge, so its
file was never opened, never flagged, and the plan still said `COMPLETE`.

On an eight-site fixture the old planner renamed five sites and reported
`COMPLETE`; the two it silently skipped were in a test file that would have
stopped compiling.

The session now also seeds the indexed universe, filtered by word-boundary text
containment — a file that does not contain the identifier cannot reference it.
Graph-declared references are always seeded regardless of their text, because
they are explicit evidence. Any candidate that could not be opened (unreadable,
or past the 64-file session cap) is reported in `notModified`, carries the new
`SESSION_INCOMPLETE` warning, and forces `PARTIAL`.

`COMPLETE` now means every file that could mention the symbol was proven, not
that the two available sources both stayed quiet.

## Bad arguments crashed instead of refusing

Every plan engine stated its preconditions by throwing an `Error` naming its
internal parameters, so a missing or misnamed argument surfaced as
`Tool error: delete readiness requires repoRoot, rawGraph, and targetId` — an
internal signature leaking to an agent, and a crash where this package promises
a status. All nine plan tools now refuse through `INVALID_ARGS` (naming the
arguments at fault) or `NO_REPOSITORY`. `bulk_replace` keeps its own more
specific `INVALID_PATTERN` refusals.

## Default text output withheld the answer

`bulk_replace` reported `PREVIEW` with no count and no files, and `move_symbol`
reported `EVALUATED` with no verdict — the data existed but only in
`output_format: "json"`, so the default cost an extra round trip to learn what
the first call already knew. Both now carry counts, per-file breakdowns, the
verdict and the next step in text mode.

## The language server is reused between renames

Spawning and shutting down tsserver was 48% of every rename's wall time and was
paid again on every call, while the graph work costs about 0 ms. One server per
repository is now kept alive between calls.

| Rename | Before | After |
| --- | --- | --- |
| first, cold | ~1000 ms | ~650 ms |
| every one after it | ~1000 ms | 3–11 ms |

Correctness rule for the reuse: every document opened for a rename is closed
again when the client is released, so a pooled server can never answer from stale
document text, and a server that is still busy is never shared — a concurrent
caller gets its own. `shutdownRenameClients()` ends the pool explicitly; a hard
process exit reaps it.

## Internal

Helpers that were byte-identical across four or more engines moved to
`src/engines/engine-kit.js`. The SQL bare name and `move_file`'s content-only
read differed and deliberately stayed with their engines. Duplicate families
across the package dropped from nine to two.
